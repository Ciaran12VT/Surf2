# Derived Document / Symbol / Search Storage Proof

This is first-plan phase 6 storage infrastructure, not runtime activation. Schema installation and a Ready migration marker do not assert that derived indexes have been built. Documents default to Unindexed; scope discovery has no reconciliation token until the coordinator explicitly records one. The initial migration may leave all these tables empty. Read/query/source-preparation APIs require a Ready session; explicit derived writes use the provided installed session. No bootstrap selection or activation is performed here.

## SQL Ownership

- `Document` is a stable physical-file or snapshot-resource identity; diagram projection documents belong to one exact `DiagramRevision`. Nullable typed owner FKs plus mutually exclusive checks replace polymorphic target keys.
- Snapshot ownership uses `(ResourceKey, SnapshotKey)` and `(ResourceKey, RevisionKey)` against the actual domain keys. No invented `SnapshotResourceRevisionKey` is used.
- `DocumentRevision` is a successful immutable publication with source fingerprint, parser/renderer/policy versions, language, source revision and content. The current pointer is constrained to the same document. File and diagram owners are also constrained to the same document.
- `ResourceDocument` is derived membership keyed by the actual `ScopeResourceKey`, not by an interchangeable snapshot/path alias. It stores the per-entry display/locator/node/parent metadata. Locator ownership is FK-constrained to that exact membership. Scope-resource deletion cascades derived membership/locators, not documents or authoritative content.
- `SearchProjection` references exactly the revision's own `TextContent`. It covers raw files, raw SQL definitions, and the existing ordered diagram `ObjectType LabelText ImageName` projection only. Table code has no search projection: Capture owns metadata/data search and matching-column/filter information.
- `SymbolDefinition` stores immutable navigation metadata, never fulltext. `SymbolNameLookup` is a verified accelerator. ASCII-to-ASCII hashes are safe candidates; non-ASCII entries are never excluded by those hashes. Non-ASCII requests scan scoped name metadata. All equality is ultimately verified in .NET. The same policy applies to locators and physical-path registration.
- `IndexWorkItem` stores a redacted work state, lease, fingerprint and policy. It is not a successful generation. Ten-minute leases may be renewed or reclaimed after expiry; superseded document versions cannot be reclaimed or published.

## One-Source Publication

1. Register/resolve the typed owner with `RegisterAsync`; set only that document's explicit memberships/locators with `SetMembershipAsync` (at most 512 of each).
2. Read one authoritative source. `IndexedFileRead` opens only the selected file, computes a raw-byte SHA-256, detects its BOM/encoding, and retains a read-only lease. `PrepareDefinitionAsync`, `PrepareTableCodeAsync` and `PrepareDiagramAsync` read only the selected immutable revision. Table formatting uses a bounded, transient one-table adapter to the existing renderer, not a library load.
3. Parse only that file via `ExtractFileSymbols`, supplying an existing parser and captured language/settings. Parsing is CPU work for the later bounded scheduler, not for painting. Enumerate extraction to completion before publication. Do not turn parser exceptions into an empty symbol list.
4. Call `BeginWorkAsync` with the expected document rowversion, fresh publication GUID, fingerprint and exact policy versions. This marks any previous generation stale, without deleting it.
5. Call `PublishAsync`. It rechecks work ownership/lease/version, verifies the source, and commits content, revision, bounded symbol TVP batches, projection and current pointer together. A physical publication reopens and checks the authoritative file and holds its read lease through commit. Definition text is verified exactly against the sealed current source revision; table/diagram rendering is independently verified. Recovery by publication GUID verifies document, content, fingerprint, language and policy before returning the original revision.
6. On failure/cancellation, call `FailWorkAsync` with a controlled code such as `ParserFailed`, not an exception message. The old revision/symbols remain visible with non-current freshness. Never publish empty replacement content for a failed read/parse. Work errors before commit do not erase authoritative content.

The table/diagram renderer constants identify supported representations. `PolicyVersion` must bind captured parser settings/language mapping and applicable culture/newline/rendering policy. Changed policies are detected by comparing the returned revision policy metadata and scheduling affected sources, not by reparsing the scope.

## Scoped Metadata And Search

`CaptureContextAsync` freezes session epoch, scope rowversion, index generation, snapshot catalogue token and diagram catalogue token, plus workspace-unloaded scope-resource keys and optional document-key batches. Each key set is at most 512. Larger caller operations split into explicit subsets and combine coverage; a subset cannot assert full scope reconciliation. An empty supplied document batch means an empty subset, not all documents.

`ReadDocumentsPageAsync`, `LookupNamesPageAsync`, `ReadHighlightNamesPageAsync` and `ResolveLocatorPageAsync` return explicit payload-free DTOs. Pages are keyset ordered, cancellable, at most 128 rows and subject to an 8 MiB metadata budget. Locator resolution returns all verified candidates, preserving ambiguity. Both canonical and readable locators are stored; creating the locators/addresses from selected owner metadata remains the coordinator's responsibility.

Name requests contain at most 64 tokens and include simple-name fallback candidates. The cursor advances across SQL candidates even when exact verification rejects every item on a page. Continue until `Exhausted`; resolve/rank only the completed candidate set. `ReferenceMetadata.Resolve` preserves bracket/quote normalization, qualified-then-simple fallback, ambiguity, non-file preference, argument-count scoring and kind ranking. `SharedHighlightMetadata` freezes shared name/kind/style-policy metadata with no GUI objects, lazy reads or I/O callbacks. Its memory scales with the supplied names; pages/token-demand caching are available to the coordinator.

`SearchAsync` uses one metadata page and one sequentially transported document buffer at a time. Literal matching is exact `OrdinalIgnoreCase`; regex is .NET `IgnoreCase | CultureInvariant`, including cross-line matches and backreferences. No LIKE, word index, RE2 or collation prefilter can exclude content candidates. Defaults are 64 results/candidates per batch, 8 Mi characters per source and 250 ms per regex evaluation; explicit limits reject oversized units, never truncate them into successful nonmatches. Regex timeouts, missing/inaccessible files and unstable reads have distinct outcomes. Invalid patterns fail the request.

Physical content search reads the current authoritative file by default. A hit records the fingerprint actually evaluated and whether it was an authoritative-file read; a changed fingerprint is marked stale relative to the indexed revision. Indexed-copy search is always marked stale for physical files. Name search verifies file existence without reading a potentially huge body and does not claim verified content freshness. Source buffers/leases/readers are disposed on failure, cancellation or early enumeration exit; cancellation throws and never yields a successful final empty batch.

Completion, considered/scanned/matched counts, incomplete outcomes, staleness, Capture delegation, discovery reconciliation and generation changes remain separate. `Completed` means the pinned **document candidate set** was exhausted. `FullyCurrentDocumentSet` is stricter. This provider does not claim complete Object Explorer search: root/folder/category names, virtual ancestry reconstruction and Capture results belong to the subsequent coordinator/providers. `IncludesExplorerContainers` is explicitly false. Reconciliation is an explicit discovery assertion, not a watcher guarantee; future scope activation/refresh/watch-loss handling must rebuild only affected memberships/fingerprints. Immutable historical text is available only by explicitly requested document/revision identity.

Before publishing a page, the stream revalidates the captured generations. A changed generation yields no page from the obsolete context and ends with `GenerationChanged=true`, `Completed=false`. There is no UI publication, dispatcher access, background polling, full-library hydration or source write here.

## Parent Validation Hooks

- `IndexContractChecks.Run()` checks literal wildcard/Unicode semantics, whole-document .NET regex/backreferences/timeout/culture, equivalence to legacy reference ranking, immutable highlighting, payload-free summaries and truthful coverage states.
- `RunAsync()` additionally checks exact bounded streaming, oversized-source rejection and cancellation.
- `ParseSql(sql)` checks ScriptDom syntax **and** cross-column column-level CHECK constraints (the LocalDB 8141 case). All cross-column checks in the schema are table constraints.
- `RunStorageAsync(session, IndexStorageFixture)` is opt-in for a parent-owned disposable Ready fixture with one published current SQL object and its resolved snapshot scope resource. It checks initial Unindexed readiness, atomic/idempotent generation publication/recovery, exact independent content reads, context invalidation, scoped locator/name batches, unload filtering, progressive scan completion and preservation of the previous successful generation after failure. It mutates only the fixture's index slice and does not create a database or set Ready.

Parent still owns shared builds and real SQL suite execution. No tests, csproj, UI, core, domain storage, user database or source files were changed by this slice. No commits were made. Static validation parsed all 12 C# files, the DDL and 32 composed SQL statements without syntax errors. The parent reported installation/trusted-FK success before final schema tightening; the final script and hooks require its rerun. Query plans, cold/warm timings, Unicode corpus equivalence, live-file races, huge-document behavior and leak/cancellation soak remain first-plan release gates. Capture's bounded lossless JSON/scalar-row experiment is not a claim of typed SQL fast filters.
